# FFTT04M — Session changes (2026‑06‑14 → 06‑15)

Branch **blue_sky**. All items below are built (`:app:assembleDebug`) and committed.
Mobile fixes were applied identically to **FFTT04L** unless noted.

## Testing‑feedback fixes

1. **Stop capture during PLAY / PLAY PROCESSED (#2)**
   `CoughCaptureService` gained a `@Volatile playbackActive` flag; the capture loop
   drains the mic but skips analysis while set. `ViewerActivity.startPlayback` sets it
   (covers both PLAY and PLAY PROCESSED), `stopAudio` clears it. Played clips are no
   longer re‑captured as new recordings.

2. **Remove FILTER from the Listen screen (#4a)** then **match L's portrait layout**
   The noise FILTER was removed from the visible Listen UI. After a first attempt left
   the EQ too wide and LATENCY/COLOR squeezed, the portrait `sliderContainer` was
   rebuilt to mirror L exactly: `weightSum 88` = EQ(54) + spacer(2) + hidden filter
   block(32, ids kept for FFT‑analysis sharing) + `listenButtonsCorner`(32) holding
   **LATENCY/COLOR at 14sp**. Top row = 70/30 BACKGROUND/GALLERY.

3. **Live mic hot‑plug + remember/reacquire chosen mic (#3)**
   `AudioDeviceCallback` now handles `onAudioDevicesAdded` too; both add/remove route
   through `handleDevicesChanged()`. New mics appear in the spinner immediately (no
   QUIT/restart). A chosen mic is no longer forgotten on disconnect — we fall back to
   the default and reacquire it (restarting capture) on reconnect.
   - **Regression fix:** a programmatic spinner rebuild fired a spurious
     `onItemSelected(0)` that overwrote the persisted `mic_device` with the default,
     preventing reacquire. Guarded with `suppressMicCallback` during rebuilds.

4. **Gallery: scroll/highlight/flash (#4b)**
   `loadFiles` saves/restores the layout‑manager scroll state across the adapter swap
   (no more jump to top on refresh; never scrolls off a highlighted selection). The
   last‑opened recording is persisted (`gallery_last_selected`) and drawn with an amber
   background on return. A freshly acquired recording (newest filename changed) gets a
   brief alpha blink, only when actually within the visible range.

5. **Bluetooth mic capture (#5)**
   The recorder previously preferred the UNPROCESSED source, which only routes to the
   built‑in mic — so a connected BT mic produced no input. BT inputs (classic SCO or LE
   Audio) now route through the communication path (`setCommunicationDevice` on API 31+,
   `startBluetoothSco` below it), force a BT‑capable source (VOICE_RECOGNITION/MIC,
   never UNPROCESSED) and 16 kHz/16‑bit PCM, with proper teardown on stop.
   - **Routing diagnostics + self‑heal:** after start we log the *actual* routed device
     (logcat tag `FFTT04M`, "Capture routed to …"); for a BT selection we re‑check after
     1.2 s and restart capture **once** if it didn't land on the BT mic (SCO warm‑up
     race). Guarded by `btRerouteAttempted`.
   - ⚠️ **Unverified on a real device** — the routed‑device log is there to make the
     next on‑device test conclusive.

6. **Phone‑decided delete after transfer (#4)**
   When the cooperative USB offer receives the desktop's ack, the phone now prompts to
   delete the recordings it just handed over (+ `.png`/`.txt`/`.json` sidecars) and
   refreshes the gallery. Explicit Delete/Keep confirm; the phone decides.
